# Scripts operacionais (spec 007)

- Arquivos: `scripts/{lib,baixar-dados,empacotar,carregar,backup,restaurar,teste-operacao,fumaca}.sh`. Alvos Make: `fetch-data` (PROFILE=mini|completo, ARGS), `bundle DEST=`, `load SRC=`, `backup`, `restore FORCE=1 [ARCHIVE=]`, `teste-operacao`, `test` (= test-portal + test-ops; spec 008 acrescenta smoke tests).
- `make subir` agora usa `OPCOES_SUBIR` (padrão `--build`); o load usa `--no-build --pull never`.
- ARMADILHA (verificada em dind offline): depois de `docker save`/`load` a imagem mantém a tag mas perde o RepoDigest; `tag@sha256:...` do .env faz o compose tentar baixar. O `carregar.sh` troca no .env da máquina alvo `ARCA_IMAGEM_*` para só a tag quando o digest não resolve. `ARCA_IMAGEM_PYTHON` é só base de build (não precisa existir na carga).
- Bundle = imagens.tar (docker save por tag) + projeto.tar (sem data/.env/.claude) + dados.tar (conteúdo: zim, maps, models, kolibri, books, comics, media; NÃO mariadb/flatnotes/kavita/jellyfin = estado, vai no backup) + manifesto.txt + SOMAS_SHA256 + carregar.sh/lib.sh. `--perfis nenhum` empacota só o núcleo. Bundle completo ~4,6 GB.
- Backup: tar.gz 600 com mariadb.sql (mariadb-dump via `compose exec`, exige MariaDB rodando), notas.tar, estado-{kolibri,kavita,jellyfin}.tar (sem conteúdo/caches), configuracao.tar (inclui .env), manifest + SOMAS_SHA256. Diretórios de dono root/uid de container são lidos/escritos via `docker run --entrypoint tar $ARCA_IMAGEM_CADDY` (imagem já presente na stack; busybox tar aceita `--exclude=./dir`).
- Restore: exige `--force`; confere SHA256; faz dump de segurança do banco atual em backups/pre-restauracao-*.sql; move notas atuais para data/flatnotes.pre-restauracao-TS; apaga só `*-wal/-shm` do SQLite antes de extrair estado; `--with-config` restaura .env/compose/Caddyfile (originais em *.pre-restauracao-TS). Limitação: SQLite de Kolibri/Kavita é copiado a quente (com wal/shm).
- fetch-data: ZIM = maior `wikipedia_pt_all_{mini|nopic}_*` listado em download.kiwix.org (mini ~1,7 GB; completo=nopic; maxi é ~20 GB) com `.sha256` publicado; download em `.part` + `curl -C -`; PMTiles via `ghcr.io/protomaps/go-pmtiles:v1.31.2 extract` (build mais recente testando datas para trás; `--network host`); Kolibri `kolibri manage importchannel|importcontent network <id>` em docker run com data/kolibri montado. IDs Studio verificados: Ciênsação 265e2427..., Khan pt-BR 2ac071c4..., Sikana pt-BR c367b7d7..., PhET pt aa254505... `--simular` e `--somente zim,mapas,modelos,kolibri`.
- Testes: `scripts/teste-operacao.sh` usa projetos Compose descartáveis (COMPOSE_PROJECT_NAME=arca-operacao-a/b, portas 8097/8098, pasta temporária). NÃO exporte o .env do projeto real nesses testes: variáveis do shell vencem o .env e derrubam o teste (ARCA_PORTA). Servidor Python próprio com Range (http.server não suporta) para testar retomada.
- E2E bundle->load: container `docker:dind` privilegiado com `--network none` + imagem derivada (apk add bash make curl coreutils tar iproute2 via `docker build --network host`), bundle montado ro; `./carregar.sh . --destino /srv/arca`.
